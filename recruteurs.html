Étude de cas

Split Expenses, du problème à l'API.

1

Le problème

Après un voyage ou dans une colocation, chacun paie une partie des dépenses. Sans méthode, cela donne de nombreux virements croisés entre les mêmes personnes.

2

L'approche

Un algorithme calcule le plus petit nombre de virements qui soldent tous les comptes. Les dépenses sont enregistrées dans une API REST documentée avec Swagger, sur une base PostgreSQL.

3

Ce que ça montre

La modélisation des données (qui a payé, qui doit quoi), une logique métier que l'on peut tester, une API documentée et mise en ligne.
